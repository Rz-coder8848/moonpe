# moonpe 项目申报书
**项目名称**：moonpe —— 纯 MoonBit 的 Windows PE/COFF 映像解析库
**项目方向**：二进制基础设施 / 可执行文件格式解析；通用性强，任何需要读取 `.exe/.dll/.sys` 的 MoonBit 程序都可复用
**仓库**：https://github.com/Rz-coder8848/moonpe
**项目性质**：原创实现，非移植；许可证 Apache-2.0；对照微软 PE 规范与 goblin(pe)、pefile（均 MIT）的行为，未复制代码，未用 FFI

**一、项目简介**：把一份 PE 映像的字节变成可查询的结构——DOS/NT 头、PE32/PE32+可选头、16 个数据目录、节表与RVA映射、导入、延迟导入、导出、调试与PDB、重定位、资源树、VERSIONINFO、TLS 回调、CLR 运行时版本、应用清单 UAC 级别、LoadConfig（含 SafeSEH 与 CFG）、证书表、运行时函数表、绑定导入，并用 `check` 把结果转成发布与安全判断。

**二、价值与生态定位**：MoonBit 已有 ELF 解析（`moonbit-community/elf`），但读不了 Windows 的 `.exe/.dll/.sys`。
已有项目 `moonar` 处理 ar 归档与 COFF 对象（`.a/.lib/.obj`）：同一个 `kernel32.dll`，moonar 报`expected ar archive magic`，moonpe 报出 PE64/8 节/104 导入/1697 导出。两者互补，共享的只有格式规定的 COFF 头与节头。

**三、预期使用场景**
1. 发布前依赖检查：列出静态导入与延迟导入，防止漏打包。例：`shell32.dll` 静态 79 个、延迟 138 个。
2. 安全初筛：用 `check` 看可写可执行节、高熵节、ASLR/DEP/CFG/SafeSEH、注入类 API 的组合，输出 ok/review/suspicious。
3. 插件校验：加载前确认位数、子系统、是否需要管理员权限（清单 `requestedExecutionLevel`）与 PDB 可用性。

**四、核心功能与工程边界**：16 个数据目录全部纳入语义支持，逐项写明"解析 / 摘要 / 规范保留"，不存在"永久只报地址"的目录。
目前未做：执行、反汇编、签名验签、.NET 元数据表、图标/位图解码。
完成标准：可选头全字段、16 目录语义分级、依赖类与结构类全读、任意截断只报错、真实系统二进制验证。

**五、实现路径与技术理解**：常见路径有"包一层 C 库""只做粗略解析""按规范从零写"三种；前两者会把平台依赖和语义错误带进调用方，我选第三种，库只依赖 core（仅 CLI 用官方 `moonbitlang/x` 读文件）。
关键理解：
1.节表 `VirtualSize` 与 `RawSize` 之间的空洞在文件里不存在，RVA 映射必须拒绝
2.真实 DLL 大量使用序号导入导出，只认名字会静默丢条目
3.32 位字段统一用 `Int64` 读再查范围，否则同一份源码在 32/64 位平台行为不同

**六、LoadConfig / SafeSEH 预期解析结果**：解析器能从 SysWOW64\kernel32.dll（PE32）和 System32\kernel32.dll（PE64）的 LoadConfig 目录提取关键安全元数据。
针对 32 位镜像，解析出结构 Size（0xc4）、SecurityCookie 虚拟地址（0x100b0170）、GuardFlags（0x10017500），并从 SEHandlerTable 解出 3 个 SafeSEH 处理函数（首个 RVA 为 0x1dfb0）以及包含 1531 项的 CFG 函数表；64 位镜像解析出 Size（0x148）和 1535 项的 CFG 表，SafeSEH 字段按架构语义标记为"不适用（N/A）"而非默认的 0。
这些都是静态元数据：审计人员可据此判断 32 位程序在编译时是否启用了 SafeSEH 与 CFG，并与同版本官方镜像的基线比对控制流表规模，识别二次链接或重打包；运行时是否强制生效仍取决于系统加载器。
注：真实样本 `kernel32`(32/64)、`shell32`、`notepad`、`mscorlib`。详见 `docs/对比说明.md`、`docs/架构说明.md`。
